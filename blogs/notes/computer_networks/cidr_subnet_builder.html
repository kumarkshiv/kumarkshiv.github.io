CIDR Subnet Builder

A CIDR block such as 192.168.10.0/24 is an address plus a prefix length. The prefix says how many of the 32 bits are the network. Try the four parts below, in order, to see how a block is read, split, sized and chosen.

Read a CIDR block

Type any IPv4 address and drag the prefix slider. Blue bits are the network part and grey bits are the host part. You can also click a bit in the mask row to set the prefix there.

Quick reference: how the prefix changes the block

Every step to the right adds one network bit and cuts the block in half.

Split a block in half

Subnetting is just borrowing one host bit to make the prefix one longer. That turns one block into two equal blocks. Start with a block, then press Split on any piece as many times as you like. Merge puts two matching halves back together.

Fit blocks to what each group needs

Real networks need different sizes. For each group, choose the smallest block that holds its hosts, then place the blocks one after another, biggest first, so every block starts on its own size boundary. This is the CIDR way of avoiding waste.

The recipe

  1. Add 2 to the hosts needed (one address for the network, one for broadcast).
  2. Find the smallest power of two that is at least that number. Its exponent is the number of host bits h.
  3. The prefix is 32 − h.
  4. Sort the groups from largest to smallest and place each block at the next address that is a multiple of its size.
